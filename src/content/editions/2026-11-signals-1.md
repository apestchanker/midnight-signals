November opens with three developments worth understanding: an integration
builders can test, protocol capabilities on the roadmap, and activity on the
production network. This edition carries forward **late-October announcements**
and a **reported early-November metrics snapshot**; these are not all releases
from November.

## 1. SIG Network: bringing Midnight privacy to Ethereum

📅 **Announced:** October 28, 2026 · **Availability:** Stagenet

SIG Network connects Compact contracts to Ethereum accounts. Applications can
keep private records on Midnight while using existing Ethereum venues and
liquidity. The underlying assets remain on Ethereum.

1. A user deposits into an Ethereum account controlled through the application.
   The application tracks the corresponding private claim on Midnight.
2. A Compact circuit checks a swap or withdrawal request and queues an Ethereum
   transaction.
3. A threshold of SIG signers jointly authorizes the transaction using
   **MPC (multi-party computation)**: one signer cannot produce the signature
   alone.
4. Ethereum executes it, and an attestation of the outcome returns to Midnight
   so the application can update its records.

The privacy boundary matters. Ethereum still exposes the account's transactions,
amounts and timing; Midnight shields the application's individual user records
and balances. Developers still need to assess what their own application
discloses across both networks.

Source: [Midnight Foundation announcement](https://midnight.network/blog/sig-network-partners-to-bring-privacy-to-applications-on-ethereum).

### Where to start building

The [SIG example repository](https://github.com/sig-net/midnight-examples) is the
practical entry point, alongside the [developer documentation](https://docs.sig.network/).
Its ERC-20 vault covers deposits, withdrawals, Uniswap swaps and Aave supply,
with deployment tooling and integration tests. Importing the `Signet` module
lets a Compact contract queue external transactions from its circuits.

A useful first experiment is a private pool in front of an existing Ethereum
application: keep user accounting and authorization on Midnight, then trace a
deposit, an external operation and its returned attestation through the example.
This provides a concrete way to understand the boundary between private state,
signing and public settlement before adapting the flow.

**Deployment status:** the announcement confirms the integration on Stagenet.
It does not establish that the integration is deployed on Mainnet.

## 2. The roadmap: proofs, enterprise keys and block production

📅 **Published:** October 27, 2026 · **Status:** planned milestones

The [October State of the Network](https://midnight.network/blog/state-of-the-network-october-2026)
introduces seven development tracks through Q1 2027. Three changes have
particularly useful implications for builders.

### Verifying ZK proofs inside Compact contracts

**Target: Q4 2026.** Midnight already uses zero-knowledge proofs to validate
private computation. The proposed feature lets application contracts check
additional proofs, including nested proofs, as inputs.

An illustrative use case is an eligibility credential: a lending application
could accept proof that a customer meets its requirements without collecting
their identity documents. The application would still need to define the claim
being proved and which issuers or verification rules it trusts.

### Enterprise keys: Ed25519 and ECDSA P-256

**Target: Q4 2026.** Contracts would verify approvals signed with these key
types, allowing integration with established enterprise signing infrastructure.

For example, a tokenized-deposit application could require a bank's approved
signature before minting or redemption. This is a contract authorization
capability, not a claim that Midnight is replacing its wallet key architecture.

### From Aura to BABE

**Targets: staged migration in Q4 2026; Mainnet migration begins Q1 2027.**
The roadmap schedules a change in block production from Aura to BABE, alongside
NIGHT staking and community block production in Q1 2027.

Aura assigns block-production turns through a scheduled rotation. BABE
(Blind Assignment for Blockchain Extension) uses randomized slot-leader
selection, supporting the transition toward a broader validator ecosystem.
Block production is distinct from finality: choosing who proposes a block is
a different job from agreeing that the block is finalized.

For application teams, this is infrastructure planning context. For prospective
operators, it is a reason to follow the rollout and participation requirements.
Permissionless contract deployment does not itself mean block production is
already open to everyone.

These dates describe intended delivery, not confirmed Mainnet activation.
Source: [Official Midnight roadmap](https://midnight.network/roadmap).

## 3. Mainnet: activity after permissionless deployment

📅 **Network milestone:** September 28, 2026 · **Reported snapshot:** approximately November 2, 2026

Midnight's March launch established its production network. On September 28,
the Foundation announced **permissionless smart contract deployment**:
developers could deploy directly to Mainnet without the previous required
Preprod security review. Applications could also deploy contracts on behalf
of end users. Testing on Preprod remains the recommended development practice.

Source: [September State of the Network](https://midnight.network/blog/state-of-the-network-september-2026).

### What the figures can tell us

The reported activity is consistent with more execution after deployment opened
up. It does not establish that the policy change caused the increase, or that
transaction growth equals user growth. Contract counts do not measure active
applications, and automated or test interactions can contribute to volume.

The next useful measurements are sustained activity, active applications,
unique users where measurable, and evidence of economic use. Public execution
counts can help track a privacy network without revealing its users' private
records, but they cannot answer every adoption question.

## The signal behind the updates

SIG gives builders a way to connect private application logic to external
liquidity. The roadmap describes new inputs and authorization tools for those
applications, alongside changes to network participation. Permissionless
deployment makes it possible for more teams to put their work on Mainnet.
Sustained, measurable use will show how that expanded opportunity translates
into adoption.
